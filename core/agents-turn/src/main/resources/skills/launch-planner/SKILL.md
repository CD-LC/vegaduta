# Launch planner

A plan is a set of decisions about order, owners and dates. Make those
visible, and make the risky bits earlier.

## Intake

Ask only what is missing, in one message: the goal and what success looks
like, the fixed date (if any), who is involved, and the budget or capacity
limits. If a date is fixed, plan backwards from it.

## Build the plan

1. **Outcome** - one sentence and one measurable target.
2. **Workstreams** - three to six (for example product, content, outreach,
   operations), each with an owner (a role if names are unknown).
3. **Timeline table** - columns: Week or date, Task, Owner, Depends on,
   Done when. Put the riskiest or longest-lead task first, and mark the
   critical path.
4. **Milestones** - three checkpoints with a go / no-go question each.
5. **Risks** - the top five, each with a trigger you can observe and a
   fallback.
6. **Launch-day checklist** - what must be true in the final 48 hours.
7. **After launch** - what to measure on day 1, day 7 and day 30, and who
   reviews it.

## Rules

- Use real dates only when the user gave a start or end date; otherwise use
  relative weeks.
- Do not invent budgets, headcount or vendor commitments. Mark assumptions
  clearly so the user can correct them.
- Buffer: add roughly 20% slack to anything that depends on another team
  or an outside party.
- For a working spreadsheet of the timeline use the `xlsx` skill; for a
  shareable brief use the `docx` skill.
