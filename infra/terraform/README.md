# Terraform reference modules

> **Reference modules, community-supported.** These modules are **not used by
> the Docker Compose or Helm install paths** and no root module/environment
> ships with them. They are building blocks for people who want to run
> VegaDuta on managed cloud services and are willing to own the result.
> Every module passes `terraform validate`; none is exercised by CI against a
> real cloud account, so run `terraform plan` and review it before applying.

| Group | Modules | Provider |
|---|---|---|
| Azure | `azure-network`, `azure-container-environment`, `azure-container-app`, `azure-database`, `azure-redis`, `azure-registry`, `azure-identity`, `azure-secrets`, `aks` | `hashicorp/azurerm` 4.x (+ `random`, `time`) |
| GCP | `gcp-network`, `gcp-compute-run`, `gcp-database`, `gcp-artifact-registry`, `gcp-iam`, `gcp-secrets`, `gcp-tunnel-vm`, `gcp-billing-guard` | `hashicorp/google` 6.x-7.x (+ `random`, `archive`) |
| AWS | `aws-network`, `aws-eks`, `aws-rds-postgres`, `aws-elasticache`, `aws-s3`, `aws-irsa-core`, `aws-secrets` | `hashicorp/aws` >= 5.81, < 7.0 (+ `random` for `aws-elasticache`) |
| Cloudflare | `cloudflare-dns`, `cloudflare-tunnel`, `cloudflare-waf`, `cloudflare-access` | `cloudflare/cloudflare` **4.x** |
| Cloudflare | `cloudflare-ai-gateway` | `cloudflare/cloudflare` **5.x** (use a separate root module) |
| Other | `upstash-redis` (pass-through, no provider) | none |

Each module pins its providers in its own `versions.tf` (Terraform >= 1.5.0).

## Secure defaults worth knowing

- `azure-secrets`: purge protection **on**, Key Vault firewall **default
  Deny** (+ `AzureServices` bypass). Add the egress IP of whatever runs
  `terraform apply` to `allowed_ip_cidrs`, or secret writes are denied.
- `aks`: a public API server requires `api_server_authorized_ip_ranges`
  unless `private_cluster_enabled = true`.
- `azure-container-app` / `gcp-compute-run`: images must be tagged or
  pinned by digest; `:latest` is rejected. Sidecar images are pinned.
- `aws-eks`: private API endpoint by default; a public one needs
  `public_access_cidrs` (`0.0.0.0/0` is rejected). Nodes require IMDSv2 with
  hop limit 1.
- `aws-rds-postgres`: encrypted, TLS-only (`rds.force_ssl`), deletion
  protection **on**, master password generated by Terraform into Secrets
  Manager and **not rotated** (it is in state; `rds_managed_master_password`
  opts into RDS rotation, which needs a pod restart after each rotation).
  **No Apache AGE on RDS: install the chart with `global.postgresql.age=false`.**
- `aws-elasticache`: TLS in transit and at rest always on, AUTH token required
  (in Secrets Manager and, unavoidably, in state), cluster mode off.
- `aws-eks`: the VPC CNI network policy agent is on, so the chart's default-deny
  NetworkPolicies are enforced (`enable_network_policy`; not run against a cluster).
- `aws-s3`: public access blocked, TLS-only, a listed set of object actions
  denied to every principal except the listed IRSA role (a guard rail, not a hard
  boundary). `aws-irsa-core`: object access on one
  bucket, nothing else. With these, `global.objectStorage.credentials=default`
  needs no keys in the cluster.
- Outputs carrying passwords, keys or tokens are marked `sensitive`. State
  still contains them: use an encrypted, access-controlled remote backend.
- PgBouncer sidecars are hard-wired to **session** pooling. Transaction
  pooling breaks schema-per-tenant isolation; do not change it.

## Minimal usage

```hcl
terraform {
  required_version = ">= 1.5.0"
  required_providers {
    azurerm = { source = "hashicorp/azurerm", version = "~> 4.40" }
    random  = { source = "hashicorp/random", version = "~> 3.6" }
  }
}

provider "azurerm" {
  features {}
}

resource "azurerm_resource_group" "this" {
  name     = "vegaduta-rg"
  location = "westeurope"
}

module "network" {
  source              = "./modules/azure-network" # or a git::https://... ref
  resource_group_name = azurerm_resource_group.this.name
  location            = azurerm_resource_group.this.location
}

module "database" {
  source                       = "./modules/azure-database"
  resource_group_name          = azurerm_resource_group.this.name
  location                     = azurerm_resource_group.this.location
  database_subnet_id           = module.network.database_subnet_id
  postgres_private_dns_zone_id = module.network.postgres_private_dns_zone_id
}
```

### AWS wiring (sketch)

```hcl
provider "aws" {
  region = "us-east-1" # your region
}

data "aws_caller_identity" "current" {}

locals {
  core_role_name = "vegaduta-core"
}

module "network" {
  source           = "./modules/aws-network"
  eks_cluster_name = "vegaduta-eks"
}

module "eks" {
  source       = "./modules/aws-eks"
  cluster_name = "vegaduta-eks"
  subnet_ids   = module.network.private_subnet_ids
}

module "database" {
  source                     = "./modules/aws-rds-postgres"
  vpc_id                     = module.network.vpc_id
  subnet_ids                 = module.network.private_subnet_ids
  allowed_security_group_ids = [module.eks.cluster_security_group_id]
}

module "cache" {
  source                     = "./modules/aws-elasticache"
  vpc_id                     = module.network.vpc_id
  subnet_ids                 = module.network.private_subnet_ids
  allowed_security_group_ids = [module.eks.cluster_security_group_id]
}

module "storage" {
  source                 = "./modules/aws-s3"
  bucket_name            = "vegaduta-files-${data.aws_caller_identity.current.account_id}"
  allowed_principal_arns = ["arn:aws:iam::${data.aws_caller_identity.current.account_id}:role/${local.core_role_name}"]
}

module "irsa" {
  source            = "./modules/aws-irsa-core"
  role_name         = local.core_role_name
  oidc_provider_arn = module.eks.oidc_provider_arn
  oidc_provider_url = module.eks.oidc_provider_url
  bucket_name       = module.storage.bucket_name
}
```

Each module's README has a "Wiring into the chart" section; the data modules
list the Helm values their outputs feed
(`global.postgresql.*` with `age=false`, `global.valkey.*` with `tls=true`,
`global.objectStorage.*` with `credentials=default`, and the `eks.amazonaws.com/role-arn`
ServiceAccount annotation). The AWS modules were validated with OpenTofu
(`tofu validate`) only; nothing has been planned or applied against an AWS account.

Validate a module on its own with:

```sh
cd modules/<name>
terraform init -backend=false && terraform validate
```
