# docling

A thin FastAPI adapter around IBM's Docling document parser (port 8002). Core routes uploads
through it ahead of the sidecar's `/extract` when the `docling` compose profile runs
(`app.knowledge.docling.*`, see `DoclingConversionService` in core): Docling produces layout- and
table-aware Markdown and handles Office/scanned formats the sidecar's extractor never did.

| | |
|---|---|
| Image | `services/docling/Dockerfile`, runs as the unprivileged user `docling`, `EXPOSE 8002` |
| Compose | service `docling`: compose profile `docling` in both stacks (`scripts/vegaduta up --full|--lite --profile docling`) |
| Auth | header `X-Internal-Token` equal to `DOCLING_SHARED_SECRET` (compared in constant time), on every endpoint except `/health`. Without the secret every other endpoint answers 503. `DOCLING_AUTH_REQUIRED=false` turns auth off for bare local development only; never set it on a deployment |
| Health | `GET /health` answers `{"status": "ok", "service": "docling"}` without credentials |
| Docs | the interactive API docs are off on purpose (the service is published on a host port) |

## Contract

`POST /extract` speaks the sidecar's contract verbatim, so the Java caller
(`SidecarConversionClient`) needs no new wire code:

```json
{"filename": "report.docx", "content_base64": "...", "ocr_provider": null, "ocr_api_key": null}
```

returns `{"text": "<extracted text as markdown>"}`. `ocr_provider`/`ocr_api_key` are accepted but
ignored — Docling runs its own OCR pipeline internally. Supported extensions (mirrored by
`DoclingConversionService.EXTENSIONS` on the Java side — the two lists must move together):
`.pdf .docx .pptx .xlsx .html .htm .csv .png .jpg .jpeg .webp .tiff .tif .bmp`.

Errors: invalid base64, an unsupported extension, an unparseable file or an empty extraction all
answer 400; unexpected parser errors answer 500.

## Configuration

| Variable | Meaning |
|---|---|
| `DOCLING_SHARED_SECRET` | the `X-Internal-Token` both sides share; generated by `scripts/vegaduta secrets` |
| `DOCLING_AUTH_REQUIRED` | `false` disables auth for bare local dev only (compose sets `true`) |
| `DOCLING_LOG_LEVEL` | logging level, default `INFO` |

## Models

The first conversion downloads Docling's layout/table/OCR model artifacts from Hugging Face —
several GB, cached under `HF_HOME` (`/app/.cache/huggingface` in the image). The Dockerfile
pre-bakes them at build time via `docling-tools models download` so a deploy on a host without
Hugging Face egress works immediately; build with `--build-arg BAKE_MODELS=false` for a slim
local/CI image that downloads on first use instead.

## Develop

```bash
cd services/docling
pip install -r requirements.txt -r requirements-dev.txt
DOCLING_AUTH_REQUIRED=false uvicorn app.main:app --port 8002   # local only, no auth
python -m pytest tests/ -q
ruff check .
```
