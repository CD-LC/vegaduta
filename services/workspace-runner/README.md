# workspace-runner

Runs the Assistant's shell commands for core, in its own container, in the project folder the person attached
(`server.js`, Node, no dependencies, port 8090). A build command (`mvn`, `npm`, a project's own scripts) is
untrusted code, so it runs here with only the projects folder mounted, its own `HOME` for build caches and no
platform secret. Core never mounts the Docker socket to get this.

| | |
|---|---|
| Image | `services/workspace-runner/Dockerfile` (JDK 21, Maven, Node 22, git; Gradle projects bring their own `./gradlew`), runs as the unprivileged user `runner` |
| Compose | compose profile `workspace` in Lite and Personal (`scripts/vegaduta up --lite --profile workspace`); the projects folder is `VEGADUTA_PROJECTS_DIR` (default `~/VegaDuta-Projects`) |
| Auth | `Authorization: Bearer <secret>`; the secret is read from `WORKSPACE_RUNNER_SECRET_FILE` (preferred) or `WORKSPACE_RUNNER_SECRET`, generated by `scripts/vegaduta secrets`. The service refuses to start without one |
| Network | internal only; no port is published except the preview range below, on the host's loopback |
| Health | `GET /health` answers `{"status":"UP"}` without credentials |

## API

| Route | Purpose |
|---|---|
| `POST /exec` `{folder, command, timeoutSeconds, maxOutputChars}` | run `/bin/sh -c <command>` in its own process group in `folder` (relative to the projects root; refused if it leaves it). Returns `{exitCode, output, truncated, timedOut, folder}`. On timeout the group gets `SIGTERM`, then `SIGKILL` after `WORKSPACE_RUNNER_KILL_GRACE_MS`. Past the output cap the start is dropped, because build errors are at the end |
| `POST /exec` with `"background": true` | start a dev server detached on a preview port (`PORT` in its environment); returns after a short settle time with `{background, running, port, pid, output}` |
| `GET /dev` | the running dev servers |
| `POST /dev/stop` `{port}` | stop one |

Preview ports come from one range (`WORKSPACE_RUNNER_PREVIEW_PORT_FIRST`, `_COUNT`; `13210-13219` by default).
Compose publishes the same range on the host's loopback so the console can show the page; keep the two in step.
