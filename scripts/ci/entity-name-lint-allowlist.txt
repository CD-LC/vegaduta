# Allowlist for scripts/ci/entity-name-lint.sh.
#
# Format: "<kind> <key>  # reason". The reason comment is MANDATORY - the
# script fails on any entry without one, because an unexplained suppression is
# indistinguishable from a silenced bug (the exact state the gate exists to
# prevent). Same role as flyway-lint-allowed-renames.txt: a deliberate,
# human-reviewed override, not something the script verifies the safety of.
#
# Every entry below was verified on 2026-08-17 by reading each listed class's
# method-level mappings: all are deliberate splits of ONE API surface across
# several controller classes with fully DISJOINT method paths - a code-
# organisation choice, not two modules colliding. The tree boots today, which
# is Spring's own proof there is no full-path ambiguity in any of them.
#
# Known limitation, accepted deliberately: entries suppress by kind+key, so a
# NEW controller joining an already-allowlisted base path is NOT re-flagged -
# the reviewer adding it must re-verify method-path disjointness manually.
# The alternative (pinning entries to file locations) would break the gate on
# every rename/move, which in a repo this actively restructured costs more
# than the manual re-check does.

path /api                  # OnboardingController (POST /onboarding) + TenantSignupController (POST /signup) - two single-endpoint public-signup controllers in the SAME tenancy package that never grew a deeper base path; disjoint methods.
path /api/agents           # AgentController (agent CRUD) + rl.RlFeedbackController (POST /{agentId}/turns/feedback) - RL feedback deliberately mounts under the agent resource it scores; the sub-path exists in no other controller.
path /api/demo             # Five demo-surface controllers (chat/image/video/session/transcript-email) across agents+imagegen+tenancy - the public demo funnel is intentionally one URL surface split by feature module; sub-paths (/chat, /image, /video, /session, /history, /transcript-email) are disjoint.
path /api/devices          # DeviceController (pairing/register/CRUD) + DeviceDataIngestionController (screen-state/notifications/app-usage/sms) + DeviceGatewayController (claim/poll/command results) - one device surface split by concern within the SAME devices module; disjoint methods.
path /api/platform         # PlatformController (feature-flags/settings) + DemoSandboxController (demo-settings/demo-metrics) + app's PlatformHealthController (GET /health) - platform-admin surface split by concern; disjoint methods.
path /api/share/workflows  # WorkflowShareController (share CRUD/run/report) + WorkflowShareVoiceController (POST /{shareId}/turn, multipart) - voice turn split out for its multipart handling; same module, disjoint methods.
