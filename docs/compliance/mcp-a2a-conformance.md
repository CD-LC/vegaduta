# MCP and A2A conformance

The actual conformance status of the platform's Model Context Protocol (MCP) and Agent2Agent
(A2A) implementations, summarised from the two detailed pages and re-checked against the tree on
2026-10-28. Read the [pack index](README.md) for the legend and limits.

> **Conformance here means "implemented and covered by this repository's tests".** It does not
> mean interoperability has been proven. No external A2A client, no A2A technology compatibility
> kit (TCK) and no third-party MCP conformance suite has been run against these servers, and
> nothing was run against a live stack or a real authorization server. There is no protocol
> certification for either.

## MCP: where it stands

The platform is an MCP **server** (`/mcp`, `core/mcpserver`) and an MCP **client**
(`core/mcp`, `core/agents-tools`). Both speak the handshake-based protocol of revision
2025-11-25 and earlier, because the MCP Java SDK on the classpath (`mcp-core` 0.18.x) has no
constants for the stateless 2026-07-28 revision. They interoperate with peers that speak the
earlier revisions or both eras, and **not** with servers that dropped `initialize`.

Counts from the 34 rows of the alignment page: 22 Done, 4 Partly, 4 Missing, 3 not applicable,
1 mixed (P3: n/a for the client, Partly for the server).

Other MCP facts worth knowing:

- HTTP+SSE is deprecated by the spec; the platform still supports it and labels it deprecated.
  Dynamic Client Registration is spec-deprecated and kept as a fallback.
- Annotations are not part of the tool pin (the Spring AI tool definition does not carry them).
- The alignment page lists open decisions D1-D4 (default pin mode, origin default, SSE removal
  timeline, Keycloak setup for OAuth mode) and open items O1-O5; none is decided.
- The server needs Keycloak configured by the operator (audience mapper for `/mcp`, an
  `mcp_grant_id` claim) before `app.mcpserver.oauth.enabled` can work; that was not configured or
  tested against a real Keycloak.

## A2A: where it stands

The platform is an A2A **server** (agent cards, JSON-RPC, REST, in `core/agents-interop` and
`core/agents`) and an outbound **client** (tool `a2a_call_agent`). A2A 1.0.0 is the spec read; the
0.3 dialect is served alongside it, selected by the `A2A-Version` header.

| Area | Status | Evidence (path, key, test) |
|---|---|---|

| Card signing (JWS, Ed25519, JWKS at `/.well-known/jwks.json`) | **Partial**: works, deviates from section 8.4 in three ways (default-valued fields not dropped, `typ` is `JWS` not `JOSE`, no interop test against an independent verifier) | `core/agents/.../A2aCardSigningService.java`; tests `A2aCardSigningServiceTest`, `A2aCardVerifierTest`; key `app.a2a.signing.*` (enabled by default; **an unpinned instance signs with an ephemeral per-boot key**) |

**A2A message signing: none.** Agent *cards* can be signed and verified; individual A2A
*messages* carry no signature, so a receiver authenticates the caller by bearer JWT only. Message
signing is in progress on a branch, not yet released.

## Known gaps

- Neither implementation has been run against an external client, a TCK or a live authorization server.
- The platform cannot speak the stateless MCP 2026-07-28 revision until the Java SDK supports it.
- MCP tool pinning defaults to `warn`, not `enforce`.
- MCP OAuth for the server is off by default and needs Keycloak mappers that this repository does not configure.
- A2A: `ListTasks`, `SubscribeToTask`, push notifications, extended agent card and gRPC are not implemented; card signing deviates from section 8.4; no `ETag`.
- A2A had no message signing; message signing is in progress on a branch, not yet released.
- A2A task store defaults to memory.
