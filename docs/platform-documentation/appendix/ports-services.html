Ports & Service Matrix

Which service listens on which port, which Compose profile or Helm chart provides it, and whether it is reachable from outside. Three views: the Docker Compose stack, the public hostnames of a domain deployment, and the Dockerfile EXPOSE lines.

Compose
deploy/compose/docker-compose.yml (Full) and lite.yml (Lite). See Docker Compose Stack.
Kubernetes
deploy/helm/charts/*; container ports match the Compose ones, exposure is decided by your Ingress values.
Host binding
Compose publishes ports on BIND_ADDR (default 127.0.0.1). Exceptions: LiveKit (LIVEKIT_BIND_ADDR) and Caddy in the domain overlay (PUBLIC_BIND_ADDR, default all interfaces).

1. Docker Compose stack

"Host" is the published mapping (host : container). "internal" means no ports: block — reachable only on the compose network by service name (e.g. http://sidecar:8001). Most host ports can be moved with the matching *_HOST_PORT variable.

2. Public hostnames (domain deployment)

With scripts/vegaduta up --full --domain <your-domain>, Caddy routes these hosts (deploy/caddy/Caddyfile). With Helm, the same names are set in your Ingress values.

PurposeHostUpstream
Consoleapp.<your-domain>web:3000
Admin consoleadmin.<your-domain>web-admin:3001
APIapi.<your-domain>core:8080
Keycloakauth.<your-domain> (realm agentic-ai)keycloak:8080
Code intelligence (optional)codeintel.<your-domain>code-intel:8090
App builder (optional)builder.<your-domain>app-builder:8091
LiveKit (optional)livekit.<your-domain>livekit:7880

Keep sidecar, the databases, Langfuse, Temporal and the sandboxes internal. Never point a browser-facing or token-issuer URL at localhost on a server; internal compose DNS names such as http://keycloak:8080 are the sanctioned exception. scripts/vegaduta doctor checks this.
