2. core/ — modules

core/pom.xml (packaging pom, Spring Boot parent 3.4.4, java.version 21) lists the reactor modules, in build order:

audit billing crypto secrets storage speech mcp mcpserver security admin sharing
providers tenancy chat eventbus approval payments knowledge guardrails google sarvam
imagegen elevenlabs sdlc eval graphmemory codeintel documentgen agents quality voice
omnichannel devices workflow platform rl templates brief app-config app app-worker app-jobs

The directories mcp-data and mcp-stdio-proxy also exist under core/ but are not reactor modules. Areas:

  • Platform/tenancy — tenancy, security, admin, platform, billing
  • Agent runtime — agents, chat, providers, eval
  • Automation — workflow, eventbus (Kafka-backed outbox), approval
  • Knowledge — knowledge, graphmemory (Apache AGE)
  • Governance — guardrails, audit, mcp (dynamic connector registry)
  • Channels/devices — omnichannel, devices, sarvam, imagegen, elevenlabs, google
  • Infra — storage, crypto, secrets, sdlc, codeintel
  • app — the Spring Boot assembly; this is what runs. app-worker (Temporal worker) and app-jobs (scheduled sweeps) are sibling assemblies from the same codebase; see shape-api/shape-jobs in the Glossary and ADR-0001.
  • Others: speech, mcpserver, sharing, payments, documentgen, quality, voice, rl, templates, brief, app-config.

Flyway migrations

core/app/src/main/resources/db/migration/ contains controlplane/ and tenant/. Both are one combined version space (README §6) — see Conventions.

3. Two facts that explain most surprises

  1. Schema-per-tenant. Tenant isolation is a Postgres schema resolved from the request's tenant context; hence PgBouncer must stay POOL_MODE=session (README §1).
  2. Flyway versions share one namespace across controlplane/ and tenant/.
