Service Topology & Runtime Map

Every runtime service this repository ships, how it is placed by Docker Compose (Lite and Full tiers) and by the Helm charts, how the pieces reach each other, which are stateful, and which are pinned to one replica.

What "verified" means on this page
Facts are read from the declared configuration: deploy/compose/*.yml, deploy/helm/charts/*/values.yaml and deploy/README.md. Your running stack reflects the profiles and values you chose; check it with scripts/vegaduta status or kubectl get pods.
Compose
deploy/compose/lite.yml (Lite) and deploy/compose/docker-compose.yml (Full, with profiles); docker-compose.domain.yml adds Caddy and public URLs
Kubernetes
Umbrella chart deploy/helm/charts/vegaduta; each dependency bundled or bring-your-own (preview)

5. Compose network segmentation

The Full compose file uses six bridge networks: data-tier (postgres, pgbouncer, valkey, seaweedfs, keycloak-db, plus keycloak and core), observability (Langfuse, Loki, Promtail, Grafana, Prometheus, Alertmanager, valkey-exporter, seaweedfs, core), app (web, web-admin, keycloak, app-builder, core), agent-io (sidecar, code-intel, app-builder, livekit, voice-agent, redpanda, temporal*, rl-trainer, plus keycloak and core), sandbox-net (tool-sandbox, core) and mcp-stdio-net (mcp-stdio-runner, core). The Helm charts render per-component NetworkPolicy objects instead.
