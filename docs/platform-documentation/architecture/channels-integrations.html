Channels & Integrations

Ten channel types feed one agent runtime. Inbound traffic arrives on provider-specific webhook endpoints in core/omnichannel, gets normalised into channel sessions, routed to an agent, and answered through the matching outbound adapter. Contact pairing, operator handoff and per-channel plan gates sit on top. Webhook paths verified against the controllers; channel set from the ChannelType enum.

1. Channel types

ChannelType: WHATSAPP, MESSENGER, INSTAGRAM, SLACK, DISCORD, X, TELEGRAM, EMAIL, TEAMS, VOICE. WhatsApp has three distinct transports (Twilio, Meta Cloud API, and the unofficial QR path) under one type.

3. Session, pairing and routing model

  • Contacts, groups, routing: inbound senders resolve to contact records; group chats and per-channel routing rules decide which agent (or agents) may answer.
  • Pairing inbox: unknown senders land in a pairing flow — pairing sessions are keyed on the external id, so a paired contact keeps memory continuity across conversations.
  • Agent selection: on shared channels, AgentRelevanceSelector (backed by the Jev decision model) picks which agent replies.
  • Operator handoff: the request_human tool parks the conversation in the operator inbox for a human to take over.
  • Universal disconnect (2026-09-23): one disconnect path now cleanly tears down a channel linkage regardless of provider.
  • Channel health endpoints: per-channel status is exposed for ops dashboards.
  • Plan gate: whatsapp_allowed in plan_limits controls WhatsApp access per plan.

4. Voice pipeline

Two independent voice paths exist and are deliberately not unified:

PathTransportPipeline
In-app calling (core/voice)LiveKit WebRTC, browser-to-agent, zero PSTNLiveKit token issuance → push-to-talk STT → AgentChatService → TTS
PSTN voice (omnichannel/twilio)Twilio voice + relay WebSocketvoice-agent worker: Silero VAD → Whisper STT → core SSE turn → ElevenLabs TTS

All TTS output passes through SpeechTextNormalizer (core/speech) so the engine says something sensible — markdown, emoji and raw URLs are rewritten before synthesis. ElevenLabs voice cloning is BYOK per tenant (own credential table); Sarvam covers the Indic-language STT/TTS surface.

5. Credential storage

Each channel connection stores provider credentials as encrypted rows in the tenant schema (AES-256-GCM via EncryptionService) — e.g. TwilioCredential, MetaWhatsAppCredential, DiscordCredential, Google refresh tokens. Outbound adapters read them at send time; webhook inbound paths authenticate via provider signature validation rather than JWT.

6. Known risks and quirks

WhatsApp uses official paths only

WhatsApp connects through Meta's WhatsApp Cloud API or a Twilio WhatsApp sender. Unofficial personal-number clients violate WhatsApp's terms of service and are not part of this platform.
