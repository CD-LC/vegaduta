1. Assets

  • Tenant data in per-tenant Postgres schemas (conversations, knowledge, memories, agent definitions).
  • Tenant-supplied credentials (LLM provider keys, channel tokens, OAuth refresh tokens) encrypted under APP_ENCRYPTION_KEY; the key itself and wherever it is stored (deploy/compose/.env, a Kubernetes Secret).
  • Identity: the Keycloak realm, its signing keys, the tenant_id claim that selects a schema.
  • Money paths: LLM spend on platform-pool keys; for operators who enable billing, payment webhooks and plan entitlements.
  • Availability: the single tenant database and the core API (do not power-cycle a live stack to diagnose it; see Rollback & Recovery).

Boundaries that matter most: internet to core (JWT, or a per-surface credential for anonymous paths); tenant to tenant (schema selection from a claim); core to sandbox (untrusted code); core to outbound network (SSRF); operator or automation tooling to the host or cluster.

4. Known exposures and open items

Status vocabulary: open = not shown fixed in the code; fixed in code = the code change is visible; deployment = depends on how you deploy, not on the code.

How to keep this page honest
When an item is closed, change its status and cite the commit, not the intent. When a new review lands, add it to the evidence list and its date to the row. Prefer editing a row over deleting it, so the history of what was once open stays readable.
