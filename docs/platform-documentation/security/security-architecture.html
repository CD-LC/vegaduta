Any CDN or WAF in front of the deployment is outside this repository; the Compose Caddyfile (deploy/caddy/Caddyfile) sets HSTS, nosniff, a referrer policy and a 32 MB body limit, and 404s the Keycloak admin console and master realm on auth.. What core itself enforces is described below. Edge configuration status is tracked as an open item on the Threat Model.

2. Authentication

  • OAuth2 resource server, fail-closed default. SecurityConfig is registered for @Profile("!insecure"). Without the security profile the issuer/JWKS placeholders fail to resolve and startup aborts rather than serving an open API; the no-auth chain (NoSecurityConfig) exists only under an explicit insecure profile, documented as dev/CI only.
  • Issuer set, not a single issuer. The JWT decoder is built from a JWKS URI, with accepted issuers = primary issuer-uri plus the comma-separated KEYCLOAK_ADDITIONAL_ISSUERS. Full default validation (timestamps) is kept. See ADR-0005.
  • Authorized-party (azp) allowlist. Tokens must be issued to a first-party client (agentic-ai-web, agentic-ai-platform-admin, agentic-ai-mobile, agentic-ai-app, agentic-ai-ide, agentic-ai-core); a client that serves open self-registration for another product should be left out. Configurable via APP_KEYCLOAK_ALLOWED_AZP; setting it empty disables the check (documented emergency lever). A token with no azp is passed to the other validators.
  • Stateless. Session creation policy is STATELESS; CSRF is disabled because auth is bearer-token only. CORS is delegated to one shared CorsConfigurationSource.
  • Response headers. Core sets CSP default-src 'none'; frame-ancestors 'none', Referrer-Policy and Permissions-Policy; Spring's defaults add X-Content-Type-Options, X-Frame-Options and HSTS on HTTPS. These apply to the core API only (see Threat Model for the front-end origins).

3. Tenant isolation

  • Schema-per-tenant. TenantContextFilter runs after bearer validation and copies the tenant_id claim into TenantContext for the request; Hibernate resolves the Postgres schema from it (TenantSchemaResolver). Rationale: ADR-0002; data layout: Data Architecture.
  • Claim-less tokens are rejected with a 403 (after a 2026-07-15 incident that produced raw 500s); platform-admin tokens are tenant-less by design and exempt; social-login users without a tenant may reach onboarding only.
  • Tenant status gate. TenantStatusGuard refuses tokens for tenants that are not usable (e.g. a schema dropped by a failed signup).
  • Schema-name sanitization. SchemaNameSanitizer is the single place a raw string becomes a Postgres identifier (lowercase letters, digits, underscore; no leading digit). An internal SAST review found no bypass where checked.
  • Missing-context fallback. If no TenantContext is set, the resolver falls back to the public schema unless app.tenancy.fail-on-missing-context=true. Default is false; the code comment says it stays false until the authenticated_no_context counter proves empty. This is an open item on the Threat Model.
  • PgBouncer must remain session-pooling for the search_path mechanism to be safe (unverified here; recorded in project notes — see Threat Model).

4. Authorization

Route-level authorization is a long ordered authorizeHttpRequests block in SecurityConfig. Roles from Keycloak are converted to authorities (KeycloakRoleConverter) and granular permissions to PERM_* authorities (GranularPermissionConverter, PermissionAuthoritySource); anything not matched falls to anyRequest().authenticated().

4.1 Conversation ownership (session memory)

A chat session id is chosen by the client and is not a secret: it appears in tool-call logs, browser history and support tickets. Session memory (SessionMemoryService, Redis) therefore never stores a conversation under that id. Every read and write goes through a caller-scoped id:

c1:sha256( tenantId , agentId , subject , clientSessionId )

where subject is the authenticated user's JWT sub (for a delegation token, the delegating user; for a share link, the visitor token; for a channel, the external id) and agentId is the agent the caller addressed. Two callers share a history only when all four parts match, so the same client id used by another user, another tenant or against another agent lands in a disjoint list. The first append also records an owner record (tenant + subject, SETNX, same TTL as the history) under that scoped id.

Endpoints that read a conversation back by the id the client knows must derive the scoped id for the current caller (CallerSessionIds.scopedForCurrentCaller, AgentChatSessionController#scopedMemorySessionId) and then check SessionMemoryService.isOwnedBy on that id, in addition to the agent-level RUNNER permission:

EndpointCheck (as coded)
GET /api/agents/{agentId}/sessions/{sessionId}/transcriptRUNNER on the agent + owner of the scoped session; otherwise 404 (same as a session that does not exist)
GET /api/agents/{agentId}/sessions/{sessionId}/exportAs above, plus CHAT_EXPORT_ENABLED; one audit entry per export, counts only
POST /api/agents/{agentId}/chat/sessions/{sessionId}/rewindRUNNER; operates on the caller's own scoped list, so it can only truncate the caller's conversation
GET .../sessions/{sessionId}/messages/{messageId}/siblings, PUT .../messages/active-leaf, POST .../messages/{messageId}/edit|regenerate (chat branching)RUNNER + APP_CHAT_BRANCHING_ENABLED; the live transcript read/written is the caller's own scoped list. The branch tree (Postgres, keyed by the raw client id) is bound to the first subject whose own turns it records or who changes its active branch; any other caller gets 404
GET /api/agents/{agentId}/chat-branching/capabilitiesRUNNER + flag; reports whether branching is on, no session data

A session with no owner record (expired, started before owner records existed, Redis unavailable) is not readable by anyone: the check fails closed. History and owner record expire together (app.chat.session-ttl-hours, 24h by default). Looking a session up by the raw client id is a bug, not a fallback; it finds nothing (regression fixed 2026-10-10, see CHANGELOG).

5. Deliberately unauthenticated surfaces

These are permitAll() at the Spring layer because the caller cannot hold a Keycloak token; each is expected to authenticate its own credential inside the controller. Anything new under these prefixes is anonymous by default.

Actuator edge guard. Requests to non-public actuator paths that carry a proxy forwarding header (which any request via a CDN, Ingress or Caddy has, and an in-network scrape lacks) get a 404 unless they present an optional scrape token. It exists so that keeping metrics private does not depend on an edge rule.

6. Agent action controls

  • Tool-output guardrails. GuardrailService is the seam every tool output passes through before re-entering the model (GuardedToolCallback). Default implementation is semantic (app.guardrails.implementation); a regex pattern variant is the opt-out. The source itself calls the pattern version "deliberately modest" and disclaims solving prompt injection or DLP.
  • Content guardrails. PII, jailbreak, policy, profanity, toxicity and tenant custom-rule guardrails (core/guardrails/.../impl), managed through /api/guardrails/rules behind PERM_MANAGE_GUARDRAILS.
  • Approval gating. ApprovalGateMode = POLICY_DEFAULT | ALWAYS_GATE | NEVER_GATE, mapped from an agent's autonomy tier. See Governance & Guardrails.

8. Operator and automation identity

A deployment can be taken down by an operator, a CI job or an automated agent that holds a human admin identity and issues a power-cycle or delete. Recommended mitigations: a procedural rule that no one resets, stops or deletes a production host or database without an explicit human decision, and a separate identity for automation with no destructive permissions. The repository does not enforce either; they are deployment decisions.

Limits of this review
Not traced: the controller-level checks behind /scim/v2/** and /api/tenant/comp-grant; a live Keycloak realm (which can drift from the checked-in realm JSON); CDN/WAF settings; and whether each control above is in a given running image.
