Knowledge Base & RAG

The knowledge subsystem (core/knowledge) gives agents grounded retrieval over tenant-owned content. Content lives in collections of documents, is ingested by jobs and connectors, and is searched by a hybrid vector + full-text pipeline with an optional reranker. A separate graph-memory store gives agents entity/relationship recall.

FR-KB-01 · Collections & documents

A collection (KnowledgeCollectionService) is a named corpus scoped to a tenant — e.g. "support docs", "product manuals". Documents belong to exactly one collection and carry source metadata, ingestion state and hierarchical structure (a document may have parents/children, preserving manuals and multi-page sources).

Plan gates

FREE tenants are limited to max_kb_collections = 1; paid tiers are uncapped (migration V158__premium_kb_collections_uncapped.sql). Caps are data-driven via plan_limits and apply only when billing is on — see Functional Overview.

FR-KB-03 · Hybrid search & reranker

Retrieval is hybrid: a vector similarity pass over the tenant's vector_store and a full-text search pass are fused with Reciprocal Rank Fusion (RRF), so a query can win on semantics, on exact terms, or both. An optional reranker hook can re-order the fused list with a cross-encoder-style model before results are injected as context.

StageBehaviour
Vector passEmbedding similarity against the per-tenant vector store.
FTS passDatabase full-text search over chunk text.
RRF fusionRank-merge both lists; reciprocal-rank scoring, no weight tuning required.
Reranker hookOptional second-stage reorder for precision-critical collections.

FR-KB-04 · Agent-facing tools

Agents reach knowledge through two built-in tools, both routed through the guarded pipeline like every other tool call:

ToolFunction
search_knowledge_baseRuns the hybrid search pipeline for a query and returns ranked chunks with source attribution.
add_to_knowledge_baseWrites new content into a collection at runtime — e.g. persisting a confirmed answer.

FR-KB-05 · Per-tenant vector store

Embeddings are stored per tenant — tenant A's vectors are never searched for tenant B's query. Combined with schema-per-tenant data layout (see Data Architecture), retrieval is tenant-isolated at both the index and the query layer.

FR-KB-06 · Graph memory

Beyond document RAG, a graph memory layer stores entities and relationships learned from conversations and content, enabling multi-hop recall — "the customer's order" → "the order's product" → "the product's known issues" in one traversal. Graph memory participates in the session/agent/tenant memory scoping described in VD-FN-001 (FR-AGT-07).
