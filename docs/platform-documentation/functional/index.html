Functional Overview & Personas

What the VegaDūta platform does, for whom. This section is the functional specification for the product surface: each domain page enumerates capabilities as numbered feature requirements (FR-xxx-nn), states which personas they serve, and marks every item with a status badge so the reader can distinguish shipping software from roadmap.

What the platform does

VegaDūta is a multi-tenant agentic-AI platform. A tenant (a customer organisation) configures AI agents — each with its own model, provider credentials or platform-hosted pool access, tools, skills, memory, reasoning depth and guardrail posture — then exposes those agents to end users through omnichannel messaging (WhatsApp, Telegram, Slack, Email, Voice and five more), through embedded chat surfaces and share links, through workflows that orchestrate agents alongside deterministic steps, and through autonomous jobs that run agents on schedules and event triggers. Knowledge bases give agents grounded retrieval; usage is metered per call; the governance layer wraps every side-effecting tool call in verification, approval and audit machinery. External clients reach the same core through the developer API, A2A and MCP.

Billing and plans are off by default

Billing and plan gating (core/billing, core/payments, plan_limits, an optional Razorpay gateway) exist for operators who run a paid hosted service. For self-hosters they are off: the consoles hide plan and billing surfaces unless NEXT_PUBLIC_BILLING_ENABLED=1 (WEB_BILLING_ENABLED in Compose), and FREE mode resolves every tenant as the top tier for feature gates. Where the pages below mention a plan gate, it only matters if you turn billing on.

Feature status conventions

Functional items in this section carry one of three statuses, distinct from the site-wide verification badges (which describe whether a doc page was re-checked, not whether a feature shipped):

StatusMeaningHow to recognise it
live Implemented and enabled by default (or by the Compose profile / flag named on the page). Default for items in this section unless marked otherwise.
on-main Merged to main and present in the repository, but not yet in a tagged release or not verified end to end — treat as "merged, not necessarily released". Stated inline where release state was not re-verified.
draft Authored but never shipped or verified. Aspirational, not real. Always called out in a warning callout.

Plan-gated features are marked with an info callout naming the plan_limits flag or tier that controls them (see Billing and plans are off by default). Requirements that were verified against source rather than a running deployment cite the file or migration that proves them, e.g. core/agents/.../ReasoningDepth.java or V270__procedures.sql.
