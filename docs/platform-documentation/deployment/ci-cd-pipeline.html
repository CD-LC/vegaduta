CI/CD Pipelines

Eight GitHub Actions workflows live in .github/workflows/. Pull requests are gated by CI, whose summary job CI OK also covers the static gates, secret scan, DCO sign-off, dependency review and docs link check; CodeQL reports separately. Tagging vX.Y.Z runs Release, which publishes signed multi-arch images and Helm charts to GHCR. There is no hosted deploy pipeline in this repository: deployment is yours, using Docker Compose or the Helm charts (see the Deployment Guide).

Source of truth
Triggers and job names below were read from the workflow files. If this page and a workflow file disagree, the file wins.
Required checks
CI OK (the ci-ok job in ci.yml) and CodeQL OK (codeql.yml); see CONTRIBUTING.md
Registry
GHCR (ghcr.io/<owner>), images and OCI Helm charts, published only by release.yml
Supply chain
cosign keyless signatures, SPDX SBOM attestations, SLSA build provenance
Local equivalents
make test, make lint, make gates, make compose-validate, make helm-lint, make sbom

Release — what a tag produces

flowchart LR
  P[prepare] --> B[build per image x arch]
  B --> M[publish: multi-arch manifest, sign, SBOM, provenance]
  P --> C[charts: package, push OCI, sign]
  M --> R[GitHub Release]
  C --> R
  • Images. Built natively on amd64 and arm64, merged into one multi-arch manifest per image under ghcr.io/<owner>: core, core-worker, core-jobs, web, web-admin, sidecar, code-intel, app-builder, tool-sandbox, mcp-stdio-runner, voice-agent, rl-trainer, postgres, and a CloudNativePG operand variant (postgres:16-pgvector-age-<version>). Versions containing - are prereleases and do not move latest.
  • Signing. Each manifest is signed with cosign keyless (GitHub OIDC, Sigstore Fulcio and Rekor).
  • SBOM and provenance. An SPDX JSON SBOM (syft) is attested per image, and SLSA build provenance is attached.
  • Helm charts. Packaged by scripts/ci/helm-package.sh, pushed to oci://ghcr.io/<owner>/charts, signed, with provenance.
  • GitHub Release. Attaches the SBOMs, chart archives, and the source tarball vegaduta.tar.gz (with SHA256SUMS) that install.sh downloads.
cosign verify ghcr.io/<owner>/core:<version> \
  --certificate-identity-regexp '^https://github.com/<owner>/<repo>/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
gh attestation verify oci://ghcr.io/<owner>/core:<version> --repo <owner>/<repo>

Not covered by any pipeline

  • Deploying. No workflow deploys to any environment. You run Compose or Helm against your own infrastructure.
  • Database migrations. Flyway runs inside core at startup; flyway-lint.sh catches shared-namespace collisions and edits to applied migrations, not runtime conflicts.
  • Translations. Message catalogs can be regenerated by maintainers; no workflow does it.
