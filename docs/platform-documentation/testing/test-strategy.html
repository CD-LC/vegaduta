Test Strategy

How the platform is tested, layer by layer, and where each layer runs. The strategy is defined by the configuration and workflows in the repository rather than by a single test-plan document (none exists under docs/testing). Detail pages: End-to-End Suites and Quality Gates & CI Checks.

What runs automatically

ci.yml (summary check CI OK) and static-gates.yml run on every pull request; e2e.yml runs nightly and on demand. Each layer also has a local make target (make gates, make test, make lint, make compose-validate, make helm-lint).

Principles visible in the configuration

  • Real stack, no mocking at the E2E tier. The Playwright suite header states there is no mocking layer anywhere; a fresh tenant is signed up per test through POST /api/signup.
  • Tests cannot see boot-time failures. Several recorded incidents (duplicate bean names, missing @Autowired, Hibernate validation) passed compile and unit tests and failed at Spring context start. The mitigations are the bean-name gate and booting the jar: a full-reactor jar boot against a throwaway deploy-postgres before building images, with all migrations applied and Started CoreApplication logged. The rule: boot the jar before any prod image (see Build, Test & Verify).
  • Ratchets over big-bang fixes. File size and hardcoded prices are frozen at a baseline that may only go down; see Quality Gates.
  • Skips must expire. Tracked-gap skips carry an expires:YYYY-MM-DD token enforced by scripts/ci/skip-expiry.sh; opt-in credential skips do not.
  • Load tests never target production. The k6 runbook forbids the production host unless a human explicitly approves ALLOW_PROD=1, and requires an allow-listed load-test tenant so no billed LLM turns occur.
  • Prod verification is a separate step. Distinguish compiled, tested, deployed-to-staging and deployed-to-prod. A production e2e probe should use a dedicated tenant kept for that purpose.

Environment prerequisites for the heavy tiers

  • E2E needs Postgres (pgvector), Valkey, Keycloak, sidecar, core (profiles security,knowledge,mcp,e2e) and the web console; the e2e profile raises the signup rate limit (default 5 per IP per window).
  • The CI core job starts Postgres with pgvector and Apache AGE for the Maven verify; e2e.yml builds the compose stack with throwaway CI-only secrets.
  • Local Maven: JDK 21+ for core (maintainers use 24), one Maven build at a time; the parent POM's coverage profile is opt-in.
Not documented in the repository

Coverage percentages, total test counts per module, pass rates, flaky-test statistics and a coverage threshold are not recorded. JaCoCo and vitest coverage are advisory with no threshold. The eval golden-dataset pass criteria are not summarised on this page; see core/quality/eval-harness.md.
