Quality Gates & CI Checks

Every gate defined in the repository: what it checks, which script or workflow implements it, and how it is triggered. Strategy and layers are on Test Strategy; the workflows themselves are described on CI/CD Pipelines.

What to require on pull requests

CI OK (the summary job of ci.yml) and CodeQL OK (codeql.yml) are the required checks (CONTRIBUTING.md). CI OK covers the static gates (static-gates.yml, called from ci.yml), the secret scan, DCO sign-off, dependency review and the docs link check. The same static gates run locally through make gates and the .githooks/pre-push hook (enable with make hooks).

Static gates (static-gates.yml)

Called from ci.yml on pull requests and pushes to main, or by manual dispatch. Each script also runs from a shell:

Injectable constructorInjectableConstructorTest (core/app, run by mvn verify; make spring-wiring)A Spring component with several constructors and none marked @Autowired ("No default constructor found" at startup), a @ConfigurationProperties class Boot cannot bind, and a no-arg constructor that silently shadows a @Value one.Blocking

The pre-push hook runs the full static-gate suite when pushing to main, Flyway lint alone for other pushes that touch core/app/src/main/resources/db/migration, and gitleaks (when installed) on every push. git push --no-verify bypasses it.

Running the gates yourself

make gates            # all static gates
make hooks            # install the pre-push hook
make lint             # eslint + tsc, ruff, shellcheck
make test             # core, web, web-admin, python
make compose-validate
make helm-lint
