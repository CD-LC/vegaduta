Streaming: SSE & AG-UI

Transport
Server-Sent Events (text/event-stream) over HTTPS POST/GET. No WebSocket endpoint is documented on this page.
Auth
Bearer JWT for the tenant-facing endpoints ( Authentication ); share/demo streams use their own credentials.
Two wire formats
The legacy chat stream (in-band marker chunks) and the structured AG-UI stream. Both run the same turn through AgentChatService.

Response framing

  • Headers: X-Session-Id (the session id, exposed via CORS), Cache-Control: no-cache, X-Accel-Buffering: no.
  • Body is a Flux<String>: each chunk is written as its own SSE data: event. Spring adds no space after data:, so clients strip the prefix by fixed length, not by trimming.
  • An empty chunk can occur (provider empty delta, keepalive on buffered reasoning depths). Ignore it.
  • Multi-line chunks are split into several data: lines by the SSE writer.

In-band markers

ConstantValueMeaning
STREAM_ERROR_MARKER@@AGENT_CHAT_STREAM_ERROR_9f2b1c@@Chunk prefix; the rest is a failure message. Emitted only if the stream already wrote to the wire (status line committed). A failure before the first byte is a normal HTTP error instead (402, 503 and so on, via GlobalExceptionHandler).
STEP_EVENT_MARKER@@AGENT_STEP_EVENT_4d81ba@@Chunk prefix followed by single-line JSON step event (tool call, tool result, error, plan, guardrail, handoff, run start/finish). Emitted only when stepEvents:true.
INTERRUPTED_REPLY_MARKER\n\n[reply interrupted]Appended to a partially persisted reply when a turn is cancelled or the client disconnects (package-private constant in AgentChatService).
Why step events are opt-in
Many consumers read this wire format without being able to opt out: the LiveKit voice bridge (would speak the JSON aloud), omnichannel adapters (would paste it into customer messages), and IDE clients. So the trace is a property of the request, never a default. The exact step-event JSON fields were not enumerated for this page: not documented here; see AgentStepEventEmitter.

AG-UI (POST /api/agents/{agentId}/agui/run)

A protocol-shaped alternative that lets any AG-UI client (for example @ag-ui/client's HttpAgent, CopilotKit, or a hand-written SSE reader) drive an agent with no VegaDūta-specific code. It is strictly additive: same authorization, session semantics, moderation, guardrails, metering and persistence as /chat; threadId is the sessionId.

Request (RunAgentInput)

Fields: threadId, runId, parentRunId, state, messages[] (id, role, content, toolCalls, toolCallId, name), tools[], context[], forwardedProps; unknown fields are ignored. The controller runs the last user message's text (string content, or the joined text parts of an array). No user text: 400. Over the controller's maximum message length: 400. Missing threadId/runId are generated as UUIDs. A supplied runId must be 1 to 128 letters, digits, - or _ (otherwise 400). In the controller code read for this page, only the last user message and the ids are passed to the turn; tools and state are not forwarded to it.

Event sequence

RUN_STARTED{threadId,runId}
STATE_SNAPSHOT{snapshot:{sessionId,agentId}}
  TEXT_MESSAGE_START{messageId,role:"assistant"}
  TEXT_MESSAGE_CONTENT{messageId,delta}            (one per non-empty token)
  TEXT_MESSAGE_END{messageId}
  TOOL_CALL_START{toolCallId,toolCallName,parentMessageId}
  TOOL_CALL_ARGS{toolCallId,delta}                 (whole redacted args JSON as one delta)
  TOOL_CALL_END{toolCallId}
  TOOL_CALL_RESULT{messageId,toolCallId,content,role:"tool"}
  CUSTOM{name:"plan"|"guardrail"|"handoff",value:{...}}
RUN_FINISHED{threadId,runId}   or   RUN_ERROR{message,code}   (never both)
  • Every event carries type and timestamp; null fields are omitted. Each SSE frame is one single-line JSON data: value with an id: equal to its sequence number.
  • Text after a tool call opens a new assistant message with a fresh messageId.
  • A tool exception surfaces as TOOL_CALL_RESULT (content says it failed), not RUN_ERROR; the run's terminal RUN_ERROR comes only from a real stream failure.
  • Not emitted: STEP_STARTED/FINISHED, STATE_DELTA, MESSAGES_SNAPSHOT, RAW. Clients must treat these as optional. The protobuf transport is not offered.
  • A :keepalive SSE comment is sent every 15 seconds of silence; SSE clients ignore comments.
  • Pre-stream failures (unknown agent or no access: 404, malformed body: 400, tenant kill switch, guardrail 422) are plain HTTP errors with no events. A request whose Accept cannot take text/event-stream gets 406.

Resume

GET /api/agents/{agentId}/agui/runs/{runId}/events replays buffered events after a position, then attaches to the live tail if the run executes on this pod. Position: ?after=<seq> or the standard Last-Event-ID header (after wins). If the run is on another pod or its live window passed you receive the buffered history and a clean end of stream; poll again until the buffer contains RUN_FINISHED or RUN_ERROR. A rejoin is scoped to the agent in the path and to the signed-in user who started the run: for anyone else, or another agent, the stream is empty, exactly as for a run that does not exist. Companion: GET /api/agents/{agentId}/agui/tools (JSON, VIEWER) lists the agent's tools as AG-UI Tool objects (name, description, permissive parameters schema). 

sequenceDiagram
  participant U as AG-UI client
  participant A as AgUiRunController
  participant S as AgentChatService
  participant B as Run buffer (Redis)
  U->>A: POST /agui/run (Bearer JWT, Accept: text/event-stream)
  A->>A: requireAccess RUNNER
  A->>S: chat(..., stepEvents active)
  S-->>A: tokens + step events
  A->>B: record(event) returns seq
  A-->>U: data: {RUN_STARTED} id: 1
  A-->>U: data: {TEXT_MESSAGE_CONTENT} id: n
  Note over U,A: connection drops
  U->>A: GET /runs/{runId}/events?after=n
  A->>B: readAfter(n)
  A-->>U: buffered events, then live tail

Client guidance

  • Send Accept: text/event-stream and Authorization: Bearer <token> (browser EventSource cannot set the header; use fetch streaming).
  • Behind proxies keep idle timeouts above the 15 s keepalive; X-Accel-Buffering: no is already set on chat.
  • Reconnect AG-UI with Last-Event-ID. The legacy chat stream has no resume; cancel then re-ask.
