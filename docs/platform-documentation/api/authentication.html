Authentication & Authorization

Default scheme
Authorization: Bearer <access-token> — a Keycloak-issued JWT, validated by Spring's OAuth2 resource server in SecurityConfig.
Token issuer
Keycloak at https://auth.example.com, realm agentic-ai.
Stateless
No sessions, CSRF disabled (SessionCreationPolicy.STATELESS); the API never sets auth cookies.
Fail-closed
The secure chain is @Profile("!insecure"). Missing profile configuration fails startup instead of serving an open API.

Obtaining a token

Browsers and clients sign in through Keycloak (OIDC). For scripted access the repository's Postman collection uses Keycloak's standard token endpoint, POST https://auth.example.com/realms/agentic-ai/protocol/openid-connect/token, form-encoded, in two shapes: a password grant (grant_type, client_id, client_secret, username, password) and a service-account grant (grant_type, client_id, client_secret). Which Keycloak clients permit which grant is realm configuration; see Keycloak Provisioning. Never paste client secrets or tokens into shared docs or tickets; use <token> placeholders. 

curl -H "Authorization: Bearer <token>" https://api.example.com/api/agents

What a token must satisfy

  1. Signature against the JWKS at app.keycloak.jwk-set-uri (container-reachable, deliberately separate from the issuer).
  2. Default JWT validation (timestamps) via JwtValidators.
  3. Issuer must be the primary issuer-uri or one of the comma-separated KEYCLOAK_ADDITIONAL_ISSUERS. See ADR-0005. A missing additional issuer 401s every call while browser logins still look fine.
  4. Authorized party (azp) must be one of app.keycloak.allowed-azp. Default: agentic-ai-web, agentic-ai-platform-admin, agentic-ai-mobile, agentic-ai-app, agentic-ai-ide, agentic-ai-core. A client that serves open self-registration for a separate product should deliberately be left out. Setting the property empty disables the check (an emergency lever). A token with no azp is not rejected by this validator.
  5. Tenant claim. TenantContextFilter reads tenant_id; an authenticated JWT with none gets 403 with a JSON body saying the account is not linked to an organization (platform-level accounts are tenant-less by design). A tenant whose provisioning never completed also gets 403.

Authorization model

Layer 1: authorities

GranularPermissionConverter emits two kinds of authority for every JWT: ROLE_<name> from the token's realm_access.roles (KeycloakRoleConverter), and PERM_<SCOPE> from the caller's stored user_permission_grant rows via PermissionAuthoritySource. Grants bind tenant-admins too: the role seeds a full bundle, it is not a bypass.

Layer 3: per-resource access

Agents and workflows have their own sharing levels. AgentChatStreamController.chat and AgUiRunController.run call agentService.requireAccess(agentId, PermissionLevel.RUNNER); AgUiRunController.tools requires VIEWER. A caller without access gets 404 rather than 403 (anti-enumeration). Workflow run requires RUNNER (WorkflowController.run). Denied requests refused by the URL matchers are written to the audit log (authz.denied).

Why a bearer header can break a public route
permitAll() does not skip bearer processing. If a route is on the main chain and a caller sends a non-JWT Authorization: Bearer value, the resource server rejects it with 401 before the controller runs. That is why the Alertmanager webhook and the MCP/developer-API paths have their own @Order(1) chains without oauth2ResourceServer.

Environments

Deployed with a domain: API https://api.<your-domain>, Keycloak https://auth.<your-domain>. Local development runs core with Keycloak on localhost:8180 as the primary issuer (local-dev only; never a public URL) plus the additional-issuer entry for the public host. Clients must send tokens minted by the same environment they call.
